Use superpowers:executing-plans, inline execution; no subagents (user preference).

Goal: finish the supplied project without claiming unperformed game tests.
Spec: ../specs/2026-10-23-vce-flour-alternatives-design.md and the user's handoff requirements.

## Constraints and review focus
- Keep the two supplied textures byte-identical, milling 10:10 and original meal costs.
- Exactly seven named VCE recipes; no prefix-based opt-in for other mods.
- A solver invocation must never receive different flour types together.
- Delegate quantity/permissions to the original solver, keep caller-owned candidates intact.
- Retain gourmet's no-mix behavior; never globally set allowMixingIngredients=false.
- Failed patch setup must disable alternate flour use, not silently permit mixing.
- Build net472 and net10.0 independently with pinned reference/Harmony packages.
- Do not publish a completed Release until the required game verification is available.

## Task 1: Review and data scoping
- Re-run original 11 checks. Inspect current upstream XML and dependency metadata.
- Add failing regression tests for prefix lookalikes and inherited parent side effects.
- Scope XML modifications to seven concrete recipes; verify original costs and filters.
Interface: mod data remains in VCE-Flour-Alternatives; development code moves to Source.

## Task 2: Runtime and build
- Confirm private method signature against both reference assemblies.
- Add executable C# behavioral tests for the actual selection policy: single types,
  split stacks, mixed shortage, bill permissions, non-flour ingredients, retry,
  list ownership, solver exceptions and unrelated recipe names.
- Run RED, replace manual quantity prediction with separate original-solver attempts
  on filtered candidate copies, run GREEN. Keep Harmony adapter small.
- Validate exact target signature and fail closed if patch setup fails.
Interface: testable policy receives candidate list, flour identity getter, solver delegate;
adapter supplies actual game objects and calls the original patched solver with reentry guard.

## Task 3: Packaging, automation, final review
- Build both target DLLs; test metadata/signatures and packaging exclusion/failure behavior.
- Add deterministic packaging that requires both assemblies; source/tests never enter ZIP.
- Run static and C# suites, inspect package, self-review (user requests no subagents).
- Push to target repository, run CI as final confirmation, record precise evidence.
- Document Japanese install/build instructions and pending in-game acceptance matrix.
- Release only when all mandatory verification is complete; otherwise retain development artifact.
